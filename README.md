## 🎯 مسئله چیست؟

بسیاری از فروشگاه‌های خانگی هنوز سفارش‌ها را از طریق پیام‌رسان‌ها می‌گیرند، رسید پرداخت را لابه‌لای گفتگوها گم می‌کنند، موجودی انبار را از حافظه مدیریت می‌کنند و آخر ماه نمی‌دانند دقیقاً چه فروخته‌اند.

**این پروژه همان بی‌نظمی را به یک فرایند شفاف تبدیل می‌کند:**
مشتری سفارش می‌دهد ← رسید پرداخت را بارگذاری می‌کند ← مدیر فروشگاه بررسی و تأیید می‌کند ← سفارش ارسال می‌شود ← همه‌چیز ثبت و قابل گزارش‌گیری است.

---

## ✨ امکانات کلیدی

### 👤 برای مشتری
- مرور و جستجوی محصولات و مرتب‌سازی آن‌ها **بدون نیاز به ثبت‌نام**
- ورود سریع فقط با **نام و شماره موبایل** (ثبت‌نام تنها در مرحله نهایی‌سازی سفارش)
- صفحهٔ شخصی سفارش با **مبلغ کل و شمارهٔ حساب فروشگاه** (همراه با دکمهٔ کپی)
- بارگذاری عکس رسید پرداخت و ثبت آدرس و کدپستی، **هر زمان و به هر ترتیب**
- بازگشت به سفارش نیمه‌کاره حتی پس از بستن مرورگر یا رفتن به برنامهٔ بانکی
- مشاهدهٔ تاریخچه و وضعیت سفارش‌ها؛ لغو سفارش پیش از تأیید پرداخت

### 🧑‍💼 برای مدیر فروشگاه
- **داشبورد خلاصه‌وضعیت** و فهرست سفارش‌ها با اولویت‌بندی رنگی (در انتظار تأیید پرداخت، در انتظار ارسال، ارسال‌شده)
- بررسی رسیدها با سه نتیجهٔ مشخص: **تأیید / نیازمند پیگیری / رد رسید**
- **تطبیق هوشمند مبلغ رسید با مبلغ سفارش** توسط هوش مصنوعی (صرفاً راهنما؛ تصمیم نهایی همیشه با مدیر است)
- مدیریت محصولات (افزودن، ویرایش، فعال/غیرفعال، حذف) و **هشدار موجودی کم**
- موجودی انبار به‌صورت خودکار با ثبت سفارش کم می‌شود
- پنل «اطلاعات ارسال» با دکمه‌های کپی برای تحویل سریع اطلاعات به سرویس پیک
- گزارش‌های فیلتری بر اساس وضعیت، بازهٔ زمانی، نام و شمارهٔ تماس مشتری، به‌همراه نمودار فروش ۷ روز اخیر
- ویرایش شمارهٔ حساب فروشگاه از داخل پنل، بدون نیاز به برنامه‌نویس

## 🧱 مدل داده

| موجودیت | نقش |
|---|---|
| `User` | کاربران سیستم (مدیر / مشتری) |
| `CustomerProfile` | اطلاعات مشتری: نام، موبایل، آدرس، کدپستی |
| `Product` | محصول، قیمت، موجودی و آستانهٔ هشدار موجودی |
| `Order` / `OrderItem` | سفارش و اقلام آن (با ثبت نام محصول در لحظهٔ خرید) |
| `Payment` | پرداخت سفارش، همراه با فهرست رسیدها و نتیجهٔ بررسی |
| `Shipment` | وضعیت ارسال |
| `StoreSettings` | تنظیمات فروشگاه (مثل شمارهٔ حساب) |

---

## 🔄 چرخهٔ سفارش

```
انتخاب محصول → ورود با موبایل → «در حال تکمیل»
      → آدرس + رسید پرداخت → ثبت نهایی (کسر موجودی)
      → بررسی رسید توسط مدیر → آماده‌سازی → ارسال → تحویل
```

## 🧭 اصول طراحی

- **MVP واقعی:** فقط آنچه برای حل مشکل عملیاتی لازم است؛ بدون افزودن امکانات اضافه.
- **منطبق بر فرایند واقعی کسب‌وکار:** مدیر «رسید» را تأیید می‌کند، نه یک مرحلهٔ جداگانهٔ تأیید سفارش.
- **گزارش‌های عملیاتی، نه تحلیلی:** فهرست‌های فیلترشده به‌جای داشبوردهای پیچیده.
- **رابط کاملاً فارسی و راست‌به‌چپ** و **واکنش‌گرا** برای موبایل، تبلت، لپ‌تاپ و دسکتاپ.
- **شفافیت دربارهٔ محدودیت‌ها:** تصمیم‌های مصالحه‌ای (مثل ورود بدون OTP یا امکان منفی‌شدن موجودی در سناریوهای خاص) به‌صراحت مستند شده‌اند.
